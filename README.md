# Barcelona TIE Cita Bot

Home Assistant add-on для двух заявителей: Антон и Наталья. Python 3.12, Playwright и графический Chromium, локальная SQLite, русский интерфейс, Telegram и SMTP. Поиск идёт через обычный интерфейс `Presentación sin Cl@ve`. CAPTCHA, SMS, неизвестные экраны и окончательное подтверждение передаются человеку.

Ключевое свойство: при возможной записи планировщик останавливается, а `browser`, `context`, `page` остаются живыми. noVNC через Home Assistant Ingress показывает **ту же вкладку**, без повторного входа. Сохранение сессии не резервирует место. Календарь не считается подтверждением.

## Установка

Добавьте репозиторий `https://github.com/Beerlogger01/TIE-CITA-BOT` в Home Assistant: **Настройки → Дополнения → Магазин дополнений → ⋮ → Репозитории**. Затем найдите «Barcelona TIE Cita», установите и откройте Web UI.

[Добавить репозиторий в Home Assistant](https://my.home-assistant.io/redirect/supervisor_add_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2FBeerlogger01%2FTIE-CITA-BOT)

Подробная инструкция и локальный вариант установки: [barcelona_cita/DOCS.md](barcelona_cita/DOCS.md). Внешние порты не нужны. Первая сборка скачивает Chromium и может занять заметное время на Pi.

Это первая версия для контролируемой проверки. Успех на официальном портале, работоспособность на физическом Pi 4 и завершение реального бронирования не заявляются без отдельной проверки. Матрица фактических проверок и ограничений: [TEST_REPORT.md](TEST_REPORT.md).

## Разработка

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m playwright install --with-deps chromium --no-shell
.venv/bin/python -m pytest -q
```

Тесты используют только локальный макет с синтетическими данными. Для полного теста noVNC нужны Xvfb, x11vnc, websockify, openbox и `/usr/share/novnc`. Проще запускать полный набор внутри образа:

```sh
docker build -t barcelona-cita:test barcelona_cita
docker build -f Dockerfile.test -t barcelona-cita:tests .
docker run --rm --memory=1500m barcelona-cita:tests
python3 scripts/container_smoke.py
```

В управляемой среде с HTTPS proxy добавьте к обеим сборкам `--secret id=proxy_ca,src=/путь/к/доверенному/ca-bundle.pem`. Сертификат используется только при сборке и не включается в образ. Проверка TLS остаётся включённой.

CI `.github/workflows/test.yaml` выполняет сборку и тесты на **нативных amd64 и ARM64** runner'ах; запуск workflow в этом рабочем каталоге сам по себе не производится. Для сборки на amd64 с `--platform linux/arm64` потребуется настроенный эмулятор; предпочтительна нативная сборка.

Runtime-зависимости закреплены с хешами в `barcelona_cita/requirements.lock`; noVNC 1.7.0 — с SHA256 архива; базовый Python-образ — с digest мультиархитектурного manifest. Debian Bookworm получает совместимые обновления безопасности; фактические версии пакетов сохраняются в `/app/system-packages.txt` внутри образа. Это не архивный snapshot Debian.

## Архитектура

```text
Официальный портал ← Chromium (одна вкладка) ← Playwright / Controller
                              ↑
                             Xvfb
                              ↑
                   x11vnc 127.0.0.1:5900
                              ↑
                  websockify 127.0.0.1:6081
                              ↑
                   aiohttp :8099 /ws + UI
                              ↑
               Supervisor Ingress (172.30.32.2)
                              ↑
                  Home Assistant + вход в HA
```

Уведомление содержит постоянную ссылку `/hassio/ingress/<slug>`. HA после авторизации создаёт собственный Ingress-путь. Токен этого пути не сохраняется в сообщении. Относительные URL сохраняют префикс Ingress для HTTP, JS-модулей и WebSocket.

`Controller` резервирует единственную проверку до первого `await`, сохраняет глобальное время попытки до навигации и блокирует повторную проверку при живой сессии. Ручное подключение отменяет задачу навигации и дожидается её завершения до разрешения VNC-ввода. Отключение клиента не возобновляет автоматизацию. Неизвестная страница сохраняется только в памяти браузера; HTML, cookies, скриншоты и трассировки на диск не пишутся.

После обычного ответа об отсутствии мест браузер закрывается для освобождения RAM. Следующая проверка создаёт новую сессию. При сохранённой сессии никакого повторного входа нет. После перезапуска живая сессия не восстанавливается: незавершённая процедура помечается `SESSION_EXPIRED`, блокировка остаётся `BLOCKED`. Подтверждённые записи и лимит частоты сохраняются.

## Границы версии

- Автоматизированы только известные первоначальные страницы до результата `Solicitar Cita`. Локаторы требуют проверки на действующей версии портала.
- Выбор офиса после обнаружения мест, даты, времени, SMS и финальное подтверждение выполняет человек. Предпочтения дат/офисов пока используются как подсказка, не как фильтр автоматического бронирования.
- Подтверждение фиксируется после ручного действия: пользователь вводит номер и дату, а программа проверяет их в текущем DOM портала вместе с явным заголовком подтверждения. Неизвестное оформление подтверждения не принимается. Реальные последующие экраны ещё не проверены.
- Автоматическое окончательное подтверждение запрещено валидатором настроек. Для будущих проверенных шагов можно добавить отдельный адаптер после изучения обезличенных экранов; обходить ручное подтверждение текущим API нельзя.
- Минимальный общий интервал 15 минут, в том числе при ручных запросах. Приоритетный четверг не ускоряет проверки ниже этого предела. После ошибки интервал растёт. При блокировке требуется явное решение пользователя после устранения причины, автоматических повторов нет.
- REST-состояния HA диагностические: это состояния API, без регистрации устройств/сущностей в entity registry. После перезапуска Core они публикуются заново не позднее следующей минуты. MQTT не используется.
- Нет контроля свободного слота на сервере и нет поддержания сессии запросами. DOM читается локально, без reload. Локальный предел актуальности не является официальным временем истечения сессии портала.
