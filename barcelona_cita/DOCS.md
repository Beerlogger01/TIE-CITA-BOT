# Установка и первое использование

## Управление в 0.3.0

На главном экране одна кнопка **«Начать / Остановить мониторинг»**, ссылка рабочего стола и настройки. Начало включает автоматическое расписание; обычный минимальный интервал и паузы после ошибок сохраняются. Разовая проверка находится в «Дополнительных инструментах».

Процесс Chromium, загрузка официального портала, пригодность страницы, пустая и зависшая вкладка показываются раздельно. Рабочий стол открывается только для пригодной страницы. Пустая вкладка при техническом сбое автоматически освобождается, затем расписание может повторить попытку после backoff. **«Восстановить работу»** отменяет активную задачу, закрывает бесполезный браузер и возвращает IDLE. Восстановление не сбрасывает время последнего запроса и паузу после ошибки; после него можно снова начать мониторинг.

При сохранённой полезной странице кнопка называется **«Завершить текущую сессию»**. Для закрытия требуется подтверждение. Если ранее были обнаружены возможные записи, защита сохраняется даже при истечении локального срока актуальности или зависании страницы. Без подтверждения Chromium не закрывается. Сначала отключите noVNC; это освобождает управление, но не возобновляет автоматизацию. После явного завершения сессии снова нажмите «Начать мониторинг». При блокировке сайта восстановление требует отдельного подтверждения после устранения причины ограничения; обхода блокировки нет.

### Telegram-получатели

1. В настройках включите Telegram, укажите **выделенный token** и HTTPS URL Home Assistant `/hassio/ingress/<slug>`. Существующий token CoC или другого polling/webhook бота для приёма команд не используйте.
2. Включите «Принимать команды», сохраните настройки. Проверьте состояние в разделе «Telegram-получатели».
3. Нажмите «Создать приглашение» и лично передайте нужному человеку показанную команду `/start КОД`. Приглашение одноразовое, действует 10 минут; в SQLite хранится только его хеш.
4. Получатель отправляет эту команду в **личный чат** боту. Chat ID определяется автоматически. Максимум два активных получателя, включая прежний список. Имя, Chat ID и подписка видны только в защищённом интерфейсе.
5. Повторите с новым приглашением для второго получателя. Кнопка теста отправляет уведомление всем активным адресатам (и другим включённым каналам).

`/status` показывает только состояние мониторинга и имя профиля разрешённому подписчику. `/stop` отключает только его подписку, поиск продолжает работать. `/help` выводит справку. Через Telegram нельзя выбирать даты, нажимать кнопки портала, подтверждать бронь или управлять мониторингом. Уведомление о календаре отличается от подтверждённой записи; URL-кнопка ведёт в HA к существующей вкладке, без cookies и NIE в ссылке.

После обновления **приём команд выключен по умолчанию**, чтобы не перехватить обновления у уже работающего бота. Старые `telegram_chat_ids` остаются в настройках и мигрируют в SQLite без удаления. Отписка/удаление имеет приоритет над статическим списком и переживает рестарт. Если в прежнем списке уже больше двух адресатов, он сохраняется, но новые подписки не принимаются до уменьшения числа активных получателей ниже двух. При смене token подписки, приглашения и offset разделяются по его хешу; данные старого бота не исчезают, но не становятся подписчиками нового автоматически.

Перед запуском `getUpdates` проверяется `getWebhookInfo`; webhook никогда не удаляется автоматически. Ответ 409 от Telegram останавливает приём команд и сохраняет состояние конфликта. После устранения причины можно нажать «Повторить проверку подключения». Bot API не позволяет доказать отсутствие другого простаивающего клиента: он обнаруживает активный конфликт 409. Поэтому выделенный token обязателен для нового polling-режима. Приём в add-on запускается одним фоновым процессом. Исходящие уведомления и мониторинг продолжаются независимо от ошибок приёма.

Изменение подписки и следующий `update_id` фиксируются одной транзакцией до отправки ответа. После сбоя повторное сообщение не выполняет операцию второй раз; отдельный ответ Telegram может быть потерян, тогда `/start` можно повторить и увидеть существующую подписку. Подписчики и cursor хранятся локально в той же приватной SQLite; Chat ID и коды приглашений не пишутся в обычный журнал.

## Установка из GitHub

1. Откройте **Настройки → Дополнения → Магазин дополнений → ⋮ → Репозитории**.
2. Добавьте `https://github.com/Beerlogger01/TIE-CITA-BOT`, обновите список магазина.
3. Найдите «Barcelona TIE Cita», установите, запустите и откройте Web UI. Внешние порты и privileged mode не нужны.
4. Затем выполните настройку профилей и уведомлений ниже. При установке из GitHub используйте фактический slug дополнения из HA, а не `local_barcelona_cita`.

## Локальная установка в Home Assistant OS

1. Проверьте, что Home Assistant OS использует `aarch64`, имеется место на SSD и возможность сборки локального дополнения. Поддерживаются aarch64 и amd64; armv7 не поддерживается.
2. Скопируйте **весь** каталог `barcelona_cita` из этого проекта в `/addons/barcelona_cita` на HA OS. Используйте доступ к каталогу локальных дополнений через Samba с включённой соответствующей общей папкой либо подходящий SSH add-on с доступом к `/addons`. `/config/addons` не заменяет `/addons`.
3. В магазине дополнений обновите список, откройте «Локальные дополнения» → «Barcelona TIE Cita» → «Установить». Сборка загружает зависимости и браузер. Затем запустите add-on и откройте Web UI. По умолчанию профили и расписание выключены.
4. Не включайте privileged mode, host networking и проброс портов. У add-on нет внешних портов. Для чтения интерфейса используется авторизация HA; по умолчанию панель административная.
5. Заполните оба профиля. NIE, ФИО и контакты вводятся только в защищённом интерфейсе. Включите нужные профили. Имя профиля в уведомлении — «Антон» либо «Наталья», не полное ФИО.
6. Настройте уведомления и сохраните настройки. Сделайте одну ручную проверку под наблюдением, затем при необходимости включите автоматическое расписание и нажмите «Запустить мониторинг».

Официальный репозиторий проекта: https://github.com/Beerlogger01/TIE-CITA-BOT. Профили и секреты вводятся только в интерфейсе установленного add-on и не хранятся в GitHub.

### Если версия 0.2.0 не установилась: `apt-get: not found`

Это ошибка конфигурации сборки add-on, исправленная в **0.2.1**. Старый `build.yaml` содержал ссылку на базовый образ с `@sha256`, которую валидатор Supervisor не принимал. Supervisor переходил к стандартному Alpine-образу, а Dockerfile пытался использовать пакетный менеджер Debian.

В 0.2.1 `build.yaml` удалён, Debian Bookworm закреплён непосредственно в `FROM`. Перед установкой обновите список репозиториев/проверьте обновления в магазине дополнений Home Assistant и убедитесь, что карточка «Barcelona TIE Cita» показывает **0.2.1 или новее**. Затем повторите «Установить». При установленной старой версии используйте «Обновить». Запускать Docker вручную на HA OS и удалять данные add-on не требуется.

CI воспроизводит параметры сборки Supervisor: `BUILD_ARCH`, `BUILD_VERSION` и старый Alpine `BUILD_FROM`. Прямой `FROM` сохраняет правильную Debian-базу даже при передаче такого legacy аргумента. Тест запуска дополнительно проверяет фактический `/etc/os-release` контейнера.

## Уведомления и удалённый доступ

В `HTTPS ссылка HA` укажите постоянный адрес:

```text
https://ваш-защищённый-home-assistant/hassio/ingress/local_barcelona_cita
```

`local_barcelona_cita` используется при локальной установке. При установке из репозитория замените `local` на реальный ID репозитория: `<repository_id>_barcelona_cita`. Slug виден в адресе страницы дополнения. Не копируйте временный `/api/hassio_ingress/<token>` и не вставляйте query-параметры, пароли или токены. Настройки принимают только HTTPS и `/hassio/ingress/<slug>`.

Используйте уже настроенный защищённый удалённый доступ HA: Home Assistant Cloud, собственный HTTPS reverse proxy с корректной конфигурацией HA либо VPN. Для доступа из другой страны ссылка должна быть достижима с телефона, а пользователь должен авторизоваться в HA. Если VPN использует внутреннее имя, настройте HTTPS и DNS внутри VPN. Открывать 5900, 6081 или 8099 наружу нельзя.

**Telegram, предпочтительный канал:** создайте личного бота, начните диалог с ним с разрешённых аккаунтов. Введите token и числовые chat ID через запятую; поддерживаются несколько получателей и отрицательные ID групп. Для прежнего режима можно оставить числовые ID. Новая автоматическая подписка по приглашениям описана выше. На каждый разрешённый chat ID отправляется сообщение и URL-кнопка «Открыть текущую сессию».

Если Telegram уже настроен в HA и есть совместимое действие `notify.<имя>`, укажите его вместо прямого token, оставив приём Telegram-команд выключенным. Это адаптер стандартного Telegram notify с `target` и `data.inline_keyboard`; совместимость конкретного notify-действия нужно проверить в вашей установке HA. Прямой Bot API — основной вариант и не зависит от версии Telegram-интеграции HA. Add-on не читает Telegram токены из конфигурации HA.

Сверено с [CoC_Telegramm](https://github.com/Beerlogger01/CoC_Telegramm): там token задаётся в настройке `telegram_bot_token` установленного add-on, а ID группы — в `clan_group_id`. Реальные значения в GitHub не сохранены. TIE использует тот же стандартный Bot API, но свои настройки и отдельный список разрешённых получателей. При использовании того же token конфликта `getUpdates` не возникает: TIE только отправляет уведомления и не запускает Telegram polling. Получатели CoC автоматически не переносятся.

**Email:** включите резервный канал, задайте SMTP сервер, отправителя, пользователя, пароль приложения и список разрешённых получателей. По умолчанию TLS на 465. Для 587 выберите STARTTLS. Незашифрованная отправка не поддерживается. Список получателей не раскрывается в заголовке To. Email отправляется параллельно Telegram и не зависит от его успеха.

**Home Assistant:** `homeassistant_api: true` даёт доступ к поддерживаемому proxy `http://supervisor/core/api`. Используется выданный Supervisor token только внутри контейнера: persistent notification и пять диагностических состояний. `hassio_api`, `auth_api`, роль manager и MQTT не требуются. Сенсоры можно выключить отдельно. Ошибки отправки видны в журнале как `NOTIFY_*_FAILED`; значение SENT означает принятие API/SMTP, а не гарантированную доставку на телефон.

В сообщениях нет NIE, email, телефона, cookies, паролей, номера подтверждения и текста портала. Telegram/SMTP получают имя профиля, состояние, время и публичный HTTPS адрес HA. Адрес HA станет известен этим сервисам и разрешённым получателям. Документы и браузерная сессия туда не передаются.

## Когда обнаружен следующий шаг

1. Бот ставит мониторинг на паузу и сохраняет Chromium, контекст и страницу. Второй профиль не запускается.
2. Откройте уведомление → защищённый HA → «Открыть текущий браузер». Если мобильный встроенный браузер Telegram не удерживает вход в HA, откройте ссылку в системном браузере. Это меняет клиент просмотра, а не серверную сессию Chromium.
3. noVNC подключается к существующему дисплею. Playwright прекращает любые действия до разрешения удалённого ввода. Не обновляйте портал без необходимости. Доступны масштабирование под экран и кнопка мобильной клавиатуры.
4. Выполните CAPTCHA/SMS/выбор места и окончательное подтверждение сами. Add-on не нажимает финальную кнопку.
5. После подтверждения вернитесь в панель, введите номер и дату с портала и нажмите «Проверить подтверждение портала». Номер, дата и распознанный заголовок должны присутствовать в текущей странице. Если формат неизвестен, запись не будет ложно помечена успешной; потребуется адаптация по обезличенному экрану.
6. Отключите noVNC кнопкой «Отключить управление». При необходимости сохраните документ подтверждения самостоятельно. Затем в панели явно завершите сессию с подтверждением и нажмите «Начать мониторинг» для второго заявителя. Подтверждённый профиль исключается из проверок, в том числе после перезапуска.

Если на портале больше нет места, завершите текущую сессию и возобновите мониторинг вручную. Автоматическое возобновление после закрытия клиента не выполняется. Кнопка остановки сохраняет найденную страницу; её закрывает только явное завершение с подтверждением в интерфейсе.

## Настройки

| Параметр | По умолчанию / назначение |
|---|---|
| Автоматическое расписание | Выключено; ручная проверка доступна отдельно |
| Обычный интервал | 15 минут, минимум 15, максимум 1440 |
| Четверг | Включено, 14:45–15:25 Europe/Madrid, 15 минут |
| Утреннее окно | Выключено, 06:00–09:00, 30 минут |
| Предупреждение ожидания | Через 10 минут сохранённой сессии |
| Предел актуальности | Через 30 минут: `SESSION_EXPIRED`, браузер остаётся открытым |
| Бюджет памяти | 1200 МБ: не начинать новую проверку при превышении |
| Допустимые даты/офисы | Локальные предпочтения для ручного выбора; автоматического выбора нет |
| Telegram / SMTP | Выключены до настройки разрешённых получателей |
| HA уведомления / состояния | Включены |
| Диагностика | Выключена; даже при включении сохраняются только коды событий |
| Ручное подтверждение | Всегда включено; выключение отвергается API |

Общий минимальный интервал применяется ко всему боту, а не к каждому профилю. Ручная кнопка также его соблюдает. При ошибках пауза удваивается с пределом 24 часа; сброс ошибки не сбрасывает время последней попытки. При неизвестной странице и ошибке с живым браузером требуется ручное решение. При блокировке не пытайтесь обходить ограничение: остановите add-on и разберитесь с причиной, затем явно сбросьте состояние. Смена IP и автоматический повтор после блокировки отсутствуют.

## Данные, ресурсы и перезапуск

Профили, секреты уведомлений, журнал и история находятся в `/data/cita.sqlite3`, каталог имеет права 0700, файл — 0600. Доступ предоставлен системному пользователю `cita` (uid 1000). Шифрование SQLite на диске не реализовано: SSD и резервные копии HA должны быть защищены владельцем. Удаление add-on с данными удаляет локальную историю. База и секреты не должны попадать в Git. Хранится максимум 1000 событий, интерфейс показывает последние 100. Скриншотов, HAR, трассировок, профилей Chromium на SSD нет. Данные временного контекста удаляются при закрытии браузера.

Один браузер, один контекст и одна вкладка. Дополнительные вкладки закрываются, переход в неизвестное место останавливает автоматизацию. Новая проверка не начинается при живой сессии. В обычном ожидании Chromium закрыт. Бюджет RAM — защитный порог старта, не жёсткий cgroup лимит и не гарантия доступной памяти на всём Pi. В интерфейсе показана память cgroup; наблюдайте общую память HA перед включением расписания. ОС при OOM может завершить процессы. Оценка реального расхода RAM/CPU на Pi ещё нужна.

Процессы Xvfb, openbox, x11vnc, websockify работают без привилегий; tini собирает дочерние процессы. В контейнере Chromium запускается с выключенной собственной sandbox, поскольку Supervisor не предоставляет требуемые user namespaces/seccomp без дополнительных полномочий. Add-on **не** запрашивает SYS_ADMIN или privileged. Системный пользователь остаётся непривилегированным, доступ ограничен Ingress, TLS проверяется, Cl@ve не используется. Это осознанное ограничение изоляции браузера; не используйте его для произвольного веб-сёрфинга.

`5900` и `6081` слушают только loopback контейнера. `8099` принимает запросы исключительно от socket peer `172.30.32.2`; поддельные X-Forwarded-For/X-Ingress-Path не дают доступа. HTTP изменения защищены CSRF, WebSocket проверяет CSRF в subprotocol, не в ссылке. Cookies HA обрабатывает сам HA.

Перезапуск уничтожает браузерную сессию. Add-on никогда не объявляет старое место доступным после рестарта. Состояние мониторинга, пауза, последняя попытка, счётчик, профили и подтверждённые записи сохраняются. Незавершённая процедура после рестарта требует явного сброса; блокировка сохраняется. SIGTERM закрывает браузер и графические процессы; принудительное выключение не позволяет восстановить прежнюю страницу.

## Диагностика

- `NO_SLOTS` — точная известная фраза после `Solicitar Cita`.
- `UNKNOWN_PAGE`, `AMBIGUOUS_OR_MISSING_*` — откройте сохранённый браузер, автоматизация не продолжает угадывать.
- `PORTAL_BLOCKED` — автоматические проверки остановлены.
- `LOCAL_SESSION_FRESHNESS_EXPIRED` — локальный предел актуальности, не доказательство официального тайм-аута или удержания места.
- `RESTART_SESSION_LOST` — после рестарта живого браузера нет.
- `NOTIFY_TELEGRAM_FAILED`, `NOTIFY_SMTP_FAILED`, `NOTIFY_HA_FAILED` — проверьте параметры и доступность соответствующего сервиса. Ответы сервисов с секретами не логируются.

При сообщении об ошибке не публикуйте исходный HTML, снимки с документами, cookies или базу. Для последующих экранов предоставляйте только вручную обезличенные материалы. Автоматического сохранения или отправки диагностики нет.

## Как убедиться, что проверка работает (0.2.2)

Сохраните включённый профиль. Для регулярной работы включите «Автоматическое расписание», сохраните настройки и запустите мониторинг. Для одиночной проверки используйте «Проверить сейчас» после снятия паузы. В панели видны текущий шаг и время разрешённой ручной проверки, даже если расписание выключено. Полная попытка ограничена 150 секундами; первая загрузка портала — 40 секундами.

Открытие браузера во время проверки теперь ждёт завершения автоматических действий. В 0.2.1 открытие noVNC отменяло загрузку и могло оставить about:blank и USER_TAKEOVER. Обычное ожидание на такой уже остановленной странице не продолжит проверку. Явная кнопка «Пауза» по-прежнему останавливает проверку для ручного вмешательства.

После сохранения Telegram/SMTP настроек нажмите «Проверить уведомления». Это тестовое сообщение, а не сообщение о найденной записи. Результат виден в журнале как NOTIFY_TELEGRAM_SENT/FAILED и аналогично для других каналов. SENT означает принятие API, а не прочтение человеком. В версии 0.2.2 входящие команды не обрабатывались. Начиная с 0.3.0 можно включить приём команд и подписку по приглашению, как описано выше.
